لبناء وكيل ذكاء اصطناعي لأندرويد، استخدم Agent Development Kit (ADK) من جوجل للغة Kotlin. وصل ADK for Kotlin إلى الإصدار 1.0 العام وصار بمميزات مطابقة تمامًا لإصداري Python وJava، مع إضافات مخصصة لأندرويد تتيح للوكيل أن يعمل بالكامل على الهاتف عبر LiteRT-LM، أو في السحابة عبر Firebase AI Logic — بكود الوكيل نفسه في الحالتين. تعرّف أدواتك بالتعليقات التوضيحية، وتعلن الوكيل، وتختار خلفية النموذج؛ والإطار يتولى التنسيق.

سبب استحقاق هذا لدليل بدلًا من رابط وثائق هو أن القرار المثير ليس الكود، بل أي خلفية تعمل عليها كل خطوة من وكيلك — وهذا الاختيار له حدود حقيقية.

## ما هو ADK for Kotlin فعلًا

ADK مجموعة أدوات تقوم على الكود أولًا: تعرّف سلوك الوكيل وأدواته وتنسيقه بالـKotlin، والإطار يملك الحلقة. وبحسب [إعلان جوجل عن الإصدار 1.0](https://developers.googleblog.com/announcing-adk-for-kotlin-10-building-production-ready-ai-agents-in-kotlin-android-and-beyond/)، يقدّم الإصدار:

- **أنظمة وكلاء هرمية** — اربط الوكلاء وفوّض المهام لوكلاء فرعيين متخصصين
- **ضغط السياق** — لخّص السجل لتبقى داخل حدود الرموز
- **تدفقات تأكيد بمشاركة الإنسان** — إيقاف، وسؤال، واستئناف
- **أدوات بالتعليقات التوضيحية** — توليد المخططات من دوال Kotlin
- **قابلية استئناف الجلسة** — تسلسل التفاعل واستعادته عبر الجلسات
- **التوافق مع Java** وخدمات الجلسة والذاكرة وRAG عبر Vertex AI

وهو مبني على نواة Kotlin Multiplatform تبقى محايدة تجاه خلفية النموذج ومخزن الجلسة ونظام الذاكرة. وهذه الحيادية هي بيت القصيد: هي ما يتيح للوكيل نفسه أن يعمل على هاتف أو خادم.

و[الكود المصدري على GitHub](https://github.com/google/adk-kotlin) برخصة Apache 2.0، و[وثائق أندرويد الرسمية هنا](https://developer.android.com/ai/adk).

## الخطوة 1 — اختر خلفية النموذج

افعل هذا قبل أن تكتب سطرًا واحدًا من كود الوكيل، لأنه يقيّد كل ما بعده.

| الخلفية | تعمل | استدعاء الأدوات | التكلفة | الأنسب لـ |
| --- | --- | --- | --- | --- |
| **LiteRT-LM** | على الجهاز (أندرويد وJVM) | نعم | مجاني | مهام دون اتصال، وخصوصية، وزمن استجابة منخفض |
| **ML Kit** (Gemini Nano) | على الجهاز (أندرويد فقط) | **ليس بعد** | مجاني | محادثة وتوليد نصي عادي |
| **Firebase AI** | السحابة (Gemini) | نعم | حسب الرموز | العمل الحقيقي: استخدام أدوات متعدد الخطوات |

لاحظ أمرين. أولًا، يُنشر ML Kit كإصدار تجريبي `-beta` و**لا يدعم استدعاء الأدوات بعد** — فأجزاء `functionCall` و`functionResponse` تُسقط، أي أنه للتوليد العادي لا للوكالة. ثانيًا، إن حاولت استخدام صنف `Gemini` من GenAI SDK مباشرة على أندرويد فستصطدم بحاجز: فهو حاليًا يمنع استخدام `API_KEY` و`GoogleCredentials` هناك. وFirebase AI Logic هو المسار المدعوم، وهو كذلك طريقة استدعاء Gemini من أندرويد دون تضمين مفتاح API في تطبيقك.

ولأن كل خلفية مجرد تطبيق لـ`Model` خلف واجهة `LlmAgent` نفسها، فتبديلها تغيير سطر واحد — ويمكنك تركيبها معًا. يستطيع وكيل على الجهاز معالجة الأدوار الرخيصة أو دون اتصال أو الحساسة للخصوصية، وتفويض الصعبة إلى وكيل سحابي داخل التسلسل نفسه.

## الخطوة 2 — أضف الاعتماديات

الوحدة الأساسية هي كل ما تحتاجه معظم المشاريع:

```kotlin
implementation("com.google.adk:google-adk-kotlin-core:1.1.0")
```

أضف معالج KSP إن أردت توليد الأدوات من التعليقات التوضيحية، ووحدة الويب إن كنت ستقدّم الوكيل عبر HTTP:

```kotlin
implementation("com.google.adk:google-adk-kotlin-webserver:1.1.0")
ksp("com.google.adk:google-adk-kotlin-processor:1.1.0")
```

للاستدلال على الجهاز أضف `google-adk-kotlin-litertlm` (يحتاج JDK 21+)، وللاستدعاءات السحابية من أندرويد أضف `google-adk-kotlin-firebase-android`. كل شيء على Maven Central تحت مجموعة `com.google.adk`.

## الخطوة 3 — عرّف أداة

الأدوات دوال Kotlin عادية مع تعليقات توضيحية. وهذا الجزء الذي يتفوق فيه ADK على معظم الأطر:

```kotlin
class SupportTools {
    @Tool
    suspend fun getOrderStatus(
        @Param("Order ID the customer is asking about") orderId: String
    ): String {
        // call your API
        return "Order $orderId shipped yesterday"
    }
}
```

يقرأ KSP هذه الدوال وقت التصريف ويولّد مخططات استدعاء الدوال. يمنحك ذلك مخططات آمنة الأنواع، ودعم دوال `suspend`، و— وهذه التفصيلة المهمة على أندرويد — **صفر انعكاس وقت التشغيل**. الانعكاس بطيء ومرتبك على الهواتف، والتوليد وقت البناء يعني أن مخطط الأداة المعطوب يصبح خطأ بناء، لا مفاجأة إنتاجية في الثانية فجرًا.

ثم اعرضها على الوكيل بالدالة المولّدة:

```kotlin
tools = SupportTools().generatedTools()
```

## الخطوة 4 — ابنِ الوكيل

إعلان الوكيل تصريحي وقصير:

```kotlin
import com.google.adk.kt.agents.LlmAgent
import com.google.adk.kt.agents.Instruction
import com.google.adk.kt.models.Gemini

val rootAgent = LlmAgent(
    name = "support_agent",
    description = "Answers customer order questions.",
    model = Gemini(name = "gemini-3.8-flash"),
    instruction = Instruction(
        "You answer order questions. Always look up the order before answering."
    ),
    tools = SupportTools().generatedTools()
)
```

الـ`instruction` هو موضع السلوك الذي يهمك. لاحظ النمط في المثال: يُطلب من الوكيل أن *يتحقق قبل أن يجيب*، لا أن يكون مفيدًا فقط. هذا السطر الواحد يمنع أكثر أنماط فشل الوكلاء شيوعًا — إجابة واثقة مبنية على لا شيء.

وإن احتاج وكيلك إلى إجراءات لا مجرد أدوات، يدعم ADK مجموعة `SkillToolset`: أدلة تشغيل عند الطلب مكتوبة كملفات `SKILL.md` يحمّلها النموذج عند الحاجة فقط. وهذه الفكرة نفسها — الكشف التدريجي — التي تقوم عليها [طريقة عمل مهارات الوكلاء](/blog/ai-agent-skills-guide) و[بروتوكول MCP](/blog/what-is-mcp-ai-agents)، وهي تُبقي فاتورة الرموز منخفضة لأن الدليل لا يدخل السياق قبل الحاجة إليه.

## الخطوة 5 — شغّله وانظر إليه فعلًا

لتقديم الوكيل محليًا مع واجهة تصحيح:

```kotlin
fun main() = AdkDevServer(AdkServerConfig.inMemory(rootAgent)).start(wait = true)
```

يستمع ذلك على المنفذ 8080 مع واجهة التطوير على `http://localhost:8080/dev-ui`، بما في ذلك نقاط التتبع ومخطط الوكيل. ومن تحذيرات الوثائق: يربط الخادم على الواجهة المحلية لأن نقاط النهاية غير موثّقة، فضع مصادقتك أمامه قبل توسيعه — وإن كنت ستنشر دون واجهة، استخدم `AdkApiServer` بدلًا منه فهو لا يثبّت الواجهة. وإن وُجد `-Dadk.web.ui.enabled=true` عالقًا في بيئة التشغيل، فسيعيد تثبيت الواجهة حتى لو قال إعدادك غير ذلك، فلا تترك هذا في الإنتاج.

## ما يجب معرفته قبل الإطلاق

- **ML Kit لا يستدعي الأدوات بعد.** إن كانت قائمة ميزاتك تتضمن «الوكيل يحجز/يغيّر/يرسل شيئًا»، فـML Kit خلفية خاطئة اليوم.
- **على الجهاز ≠ قادر.** النموذج بحجم هاتف ممتاز في التصنيف والاستخراج وأضعف في الاستدلال متعدد الخطوات. استخدمه في الحدود التي يبرع فيها وفوّض الباقي.
- **اختبر الوكيل، لا التطبيق فقط.** في الوكلاء، «شغّل» ليست «نجح» — عليك التحقق من الأدوات التي استدعاها وبأي ترتيب. و[منهج التقييم](/blog/how-to-evaluate-ai-agents) هو نفسه الذي تستخدمه مع وكيل على خادم.

## الخلاصة

يمنحك ADK for Kotlin تعريف وكيل واحدًا وثلاث خلفيات: على الجهاز مع LiteRT-LM، أو في السحابة مع Firebase AI، أو مزيج منهما. ابدأ باختيار الخلفية لكل خطوة، وعلّق أدواتك لتُولَّد مخططاتها وقت البناء، وشغّل واجهة التطوير لرؤية التتبع، وتذكّر أن ML Kit للمحادثة فقط حاليًا. الإطار هو الجزء السهل؛ أما تحديد ما تستحقه كل خطوة فهو الهندسة.
